# Python-OFFload

This script is an automated Multi-Cloud Incident Response and Containment Pipeline designed to neutralize compromised credentials instantly and simultaneously across Amazon Web Services (AWS), Microsoft Entra ID (Azure AD), and Okta. Written with an asynchronous core, the engine enforces a "zero-entropy" offboarding strategy. It fires isolation commands to all target identity providers in parallel, ensuring a malicious actor cannot leverage a delay in one cloud to pivot or destroy infrastructure in another.
Behind the scenes, the script balances synchronous and asynchronous workflows by wrapping traditional blocking calls inside dedicated runtime threads, preventing thread starvation during emergency operations. It treats error management strictly: rather than failing silently or allowing partial lockouts to pass unnoticed, the orchestration layer tracks the resolution health of each cloud task. If even a single provider fails to securely isolate the target, the entire pipeline flags a high-priority alert and exits with a failure state, giving security operations center (SOC) teams immediate, predictable feedback.

While the architecture is highly reliable, engineering around multiple upstream vendor SDKs required addressing several integration quirks. In the AWS layer, the script applies an aggressive, inline Deny-All boundary override before attempting to teardown the web surface area; if a user has no active console profile, it cleanly handles the resulting NoSuchEntity API error without crashing. The Microsoft Entra ID section utilizes the newer msgraph SDK to disable account state and universally broadcast token revocations to active desktop and mobile apps. Finally, the Okta integration features robust footprint-checking to safely handle multi-version SDK return types—specifically parsing out the user ID whether the API responds with a raw object or a legacy tuple—before clearing session tokens and suspending directory routing entirely.
